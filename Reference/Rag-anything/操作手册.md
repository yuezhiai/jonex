# atomic-rag 操作手册

## 1. 构建镜像

### 1.1 前置条件

- Docker Desktop（Windows / macOS / Linux）
- 已拉取代码 `jonex-platform`

### 1.2 构建命令

```bash
# 在项目根目录执行
cd jonex-platform\deploy

# 构建 atomic-rag 镜像（含模型预下载，约 11.8GB）
docker-compose build atomic-rag
```

构建过程分三个阶段：

| 阶段 | 内容 | 耗时 |
|------|------|------|
| 系统依赖 | libreoffice、ffmpeg、poppler-utils、tesseract-ocr（中文） | ~3 min |
| pip 安装 | raganything[all] + mineru + whisper + paddleocr + lightrag-hku 等 | ~7 min |
| 模型预下载 | Whisper base（~140MB）+ MinerU VLM/layout/OCR（~2-4GB） | ~1-5 min |

首次构建约 15-20 分钟，后续增量构建约 2-3 分钟（pip 层缓存复用）。

### 1.3 模型预下载说明

`deploy/docker/download_models.py` 在构建时自动执行，预下载以下模型到镜像内：

- **Whisper base** → `/root/.cache/whisper/`
- **MinerU**（layout / VLM / OCR 模型）→ `/root/.cache/modelscope/` + `/root/.cache/huggingface/`
- **PaddleX OCR** → `/root/.cache/paddlex/`

镜像内模型路径声明为 `VOLUME`，可通过挂载宿主机目录实现持久化复用：

```yaml
volumes:
  - jonex-rag-models:/app/models    # 模型缓存持久化
```

## 2. 启动服务

### 2.1 docker-compose 启动（推荐）

```bash
cd jonex-platform\deploy

# 开发模式（端口暴露到宿主机）
docker-compose up -d atomic-rag

# 单独启动（跳过其他服务依赖）
docker-compose up -d lightrag atomic-rag
```

### 2.2 手动 docker run

```bash
docker run -d --name atomic-rag \
  -p 8000:8000 \
  -e LIGHTRAG_API_URL=http://lightrag:9621 \
  -e LIGHTRAG_API_KEY=your_api_key \
  -e RAG_PARSER=mineru \
  -e WHISPER_MODEL=base \
  -e LLM_BINDING_HOST=http://your-llm:11434 \
  -e LLM_BINDING_API_KEY=your_key \
  -e VISION_BINDING_HOST=http://your-vlm:11434 \
  -e VISION_BINDING_API_KEY=your_key \
  -e RAG_WEBHOOK_URL=http://your-callback/rag-webhook \
  -v /host/inputs:/app/inputs:ro \
  -v /host/output:/app/output \
  deploy-atomic-rag:latest
```

## 3. 文件拷贝到容器处理目录

### 3.1 通过共享卷（推荐）

在 docker-compose 或 docker run 中挂载宿主机目录到容器的 `/app/inputs`：

```yaml
volumes:
  - /host/data/inputs:/app/inputs:ro   # 只读挂载
```

然后将文件拷贝到宿主机目录即可：

```bash
# Linux/macOS
cp document.pdf /host/data/inputs/

# Windows
copy document.pdf C:\data\inputs\
```

容器内文件路径为 `/app/inputs/document.pdf`。

### 3.2 通过 docker cp（临时）

```bash
docker cp document.pdf atomic-rag:/app/inputs/document.pdf
```

**注意**：`docker cp` 到不存在目录需先创建：

```bash
docker exec atomic-rag mkdir -p /app/inputs
docker cp document.pdf atomic-rag:/app/inputs/
```

### 3.3 文件路径约定

提交任务时使用容器内路径（不是宿主机路径）：

```json
{"file_path": "/app/inputs/document.pdf"}
```

## 4. API 接口

### 4.1 健康检查

```bash
curl http://localhost:8000/health
```

响应：

```json
{"status": "healthy", "parser": "mineru"}
```

### 4.2 提交处理任务

```bash
curl -X POST http://localhost:8000/process \
  -H "Content-Type: application/json" \
  -d '{
    "file_path": "/app/inputs/document.pdf",
    "tenant_id": "my_tenant",
    "output_dir": "/app/output"
  }'
```

请求参数：

| 字段 | 必填 | 说明 |
|------|------|------|
| `file_path` | 是 | 容器内文件路径 |
| `tenant_id` | 否 | 租户标识（默认 `default`） |
| `output_dir` | 否 | 解析产物目录（默认 `/app/output`） |

响应：

```json
{
  "task_id": "uuid-string",
  "status": "pending",
  "file_path": "/app/inputs/document.pdf"
}
```

### 4.3 查询任务状态

```bash
curl "http://localhost:8000/status/{task_id}?tenant_id=my_tenant"
```

响应：

```json
{
  "task_id": "uuid-string",
  "status": "completed",
  "progress": 1.0,
  "error": null,
  "doc_ids": ["chunk_id_1", "chunk_id_2"]
}
```

状态机：`pending → processing → completed / failed`

### 4.4 检索查询

```bash
curl -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{
    "query": "这个文档讲了什么内容？",
    "tenant_id": "my_tenant",
    "mode": "hybrid",
    "top_k": 5
  }'
```

响应：

```json
{
  "query": "这个文档讲了什么内容？",
  "answer": "文档内容是关于..."
}
```

## 5. Webhook 回调

### 5.1 配置 Webhook 接收地址

设置环境变量 `RAG_WEBHOOK_URL` 指向你的回调服务地址：

```bash
RAG_WEBHOOK_URL=http://your-service:8080/rag-webhook
```

### 5.2 回调 Payload 格式

处理完成后，atomic-rag 会 POST JSON 到 `RAG_WEBHOOK_URL`：

```json
{
  "task_id": "uuid-string",
  "tenant_id": "my_tenant",
  "status": "completed",
  "doc_ids": ["chunk_id_1", "chunk_id_2"],
  "error": null
}
```

字段说明：

| 字段 | 说明 |
|------|------|
| `task_id` | 任务 ID |
| `tenant_id` | 租户标识 |
| `status` | `completed` 或 `failed` |
| `doc_ids` | LightRAG 入库的 chunk doc_id 列表 |
| `error` | 错误信息（仅 status=failed 时有值） |

### 5.3 创建 Webhook 接收服务示例（Python FastAPI）

```python
from fastapi import FastAPI, Request

app = FastAPI()

@app.post("/rag-webhook")
async def rag_webhook(request: Request):
    """接收 atomic-rag 处理完成回调"""
    payload = await request.json()

    task_id = payload["task_id"]
    status = payload["status"]
    doc_ids = payload.get("doc_ids", [])

    if status == "completed":
        print(f"[OK] 任务 {task_id} 完成，入库 {len(doc_ids)} chunks")
        # 在这里触发后续业务逻辑：
        # - 更新数据库状态
        # - 发送通知
        # - 触发下游处理
    else:
        error = payload.get("error", "unknown")
        print(f"[FAIL] 任务 {task_id} 失败: {error}")

    return {"received": True}


if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8080)
```

### 5.4 完整调用流程

```
┌──────────┐    POST /process      ┌──────────────┐
│  调用方    │ ──────────────────→  │  atomic-rag   │
│          │ ←──── task_id ────── │              │
└──────────┘                      │  (处理中...)   │
                                  │              │
┌──────────┐   GET /status/{id}   │              │
│  调用方    │ ──────────────────→  │  1. parse    │
│  (轮询)   │ ←──── status ────── │  2. ASR转写   │
└──────────┘                      │  3. 推LightRAG│
                                  │  4. webhook → │
┌──────────┐  POST /rag-webhook   │              │
│  Webhook  │ ←────────────────── │              │
│  接收服务  │  {task_id, status,  └──────────────┘
│          │   doc_ids, error}
└──────────┘
```

## 6. 支持的格式

### 6.1 文档（Parser 处理）

| 格式 | 扩展名 | 解析器 |
|------|--------|--------|
| PDF | `.pdf` | mineru / docling / paddleocr |
| Office | `.doc` `.docx` `.ppt` `.pptx` `.xls` `.xlsx` | mineru / docling |
| 图片 | `.jpg` `.jpeg` `.png` `.bmp` `.tiff` `.webp` | mineru / paddleocr |
| Markdown | `.md` | mineru |

### 6.2 视频（完整多模态流水线）

| 格式 | 扩展名 |
|------|--------|
| MP4 | `.mp4` |
| AVI | `.avi` |
| MOV | `.mov` |
| MKV | `.mkv` |
| 其他 | `.flv` `.wmv` `.webm` `.m4v` `.mpg` `.mpeg` `.3gp` |

完整流水线（启用 `ENABLE_VIDEO_PROCESSING=true` 时）：

```
视频文件
  ├── ① ffmpeg 提取音轨（16kHz mono WAV）
  │     └── Whisper ASR 转写 → 带时间戳的文本分段
  │
  ├── ② 关键帧提取（VIDEO_KEYFRAME_ALGORITHM 控制算法）
  │     ├── interval: 均匀时间间隔采样（最快）
  │     ├── scene:   场景变化检测（内容感知）
  │     ├── iframes: I 帧位置（元数据级，无解码开销）
  │     └── hybrid:  I 帧 + 间隔填充（推荐，兼顾覆盖与成本）
  │     └── VLM 逐帧描述（OCR 文字 + 场景描述）
  │
  ├── ③ 时间对齐
  │     └── ASR 分段与关键帧按时间戳归属到同一 chunk
  │
  ├── ④ MapReduce 实体抽取
  │     └── 转录文本分批 LLM 摘要 → 递归归约 → 全局综合
  │
  └── ⑤ 推 LightRAG 知识图谱
        └── 每 chunk 携带时间轴元数据（start_time / end_time / frame_times）
```

> **无音频视频**：若视频无音轨，跳过后 ASR，直接用关键帧 VLM 描述作为伪转录文本。修复（2026-05-27）：无音频视频的 `end_time` 改用 ffprobe 获取真实视频时长（之前始终为 0）。

**所用配置项**：`ENABLE_VIDEO_PROCESSING`、`VIDEO_EXTRACT_AUDIO`、`VIDEO_KEYFRAME_ALGORITHM`、`VIDEO_KEYFRAME_INTERVAL`、`VIDEO_MAX_FRAMES`、`VIDEO_CHUNK_TOKEN_SIZE`、`VIDEO_SUMMARIZE_BATCH_SIZE`、`VIDEO_SUMMARIZE_MAX_BATCHES`、`MAX_PARALLEL_VLM`、`VLM_TIMEOUT`。

### 6.3 音频（Whisper ASR）

| 格式 | 扩展名 |
|------|--------|
| WAV | `.wav` |
| MP3 | `.mp3` |
| M4A | `.m4a` |
| OGG | `.ogg` `.opus` |
| FLAC | `.flac` |
| 其他 | `.wma` `.aac` `.amr` |

处理流程（启用 `ENABLE_AUDIO_PROCESSING=true` 时）：

```
音频文件
  ├── ① Whisper ASR 转写 → 带时间戳的文本分段（start / end / speaker_label）
  ├── ② 分段重叠合并（按 AUDIO_CHUNK_TOKEN_SIZE 控制 token 数）
  ├── ③ MapReduce 摘要 → 递归归约 → 实体抽取
  └── ④ 推 LightRAG 知识图谱（每段一个 chunk）
```

**所用配置项**：`ENABLE_AUDIO_PROCESSING`、`ASR_BINDING`、`ASR_MODEL`、`WHISPER_MODEL`、`AUDIO_ASR_TIMEOUT`、`MAX_PARALLEL_ASR`、`MIN_ASR_CONFIDENCE`、`AUDIO_CHUNK_TOKEN_SIZE`、`AUDIO_SUMMARIZE_BATCH_SIZE`、`AUDIO_SUMMARIZE_MAX_BATCHES`。

## 7. 故障排查

### 7.1 查看日志

```bash
# 容器日志
docker logs -f atomic-rag

# 跟踪特定任务
docker logs atomic-rag | grep "task_id=xxx"
```

### 7.2 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| LightRAG 连接超时 | LightRAG 未就绪 | 等待 `lightrag:9621/health` 返回 200 |
| mineru 解析失败 | 模型未下载 | 检查 `download_models.py` 是否执行成功 |
| Whisper 下载慢 | 网络问题 | 模型已预下载到镜像，检查镜像大小是否为 11.8GB |
| 任务卡在 processing | 大文件 CPU 转写慢 | 调高 `RAG_WORKER_NUM` 或用 GPU 版 Whisper |
| doc_ids 为空 | LightRAG API 不兼容 | 检查 LightRAG 镜像版本 |
